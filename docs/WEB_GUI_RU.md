# Браузерная панель

Для установки через интерфейс NAS используйте [инструкцию TrueNAS](TRUENAS_RU.md). Здесь описан обычный Docker Compose на Linux, запуск из исходников и настройка адреса панели.

## Docker Compose на Linux

1. Клонируйте репозиторий и скопируйте `.env.example` в `.env`.
2. Выберите отдельный локальный каталог состояния и существующую папку с фото и видео.
3. Замените в `.env` `STATE_DIRECTORY`, `PHOTO_LIBRARY`, `PUID`, `PGID` и `MAILRU_ALLOWED_HOSTS`.
4. Проверьте права каталогов, затем запустите контейнер.

Например, **для нового каталога состояния** на обычном Linux-сервере с UID/GID `1000:1000`:

```bash
sudo install -d -m 700 -o 1000 -g 1000 /srv/mail-cloud-state
```

Укажите `/srv/mail-cloud-state` как `STATE_DIRECTORY`. Для TrueNAS dataset создают и настраивают через его интерфейс. Существующее состояние не заменяйте пустым каталогом. Исходный каталог и его родители должны разрешать выбранной паре UID/GID чтение и проход; mount остаётся только для чтения.

Запуск контейнера:

```bash
docker compose config
docker compose pull
docker compose up -d
docker compose logs --tail=100 mailru-photos
```

Пример `.env` публикует `31800:8787`. Откройте `http://АДРЕС_СЕРВЕРА:31800`; значение `MAILRU_ALLOWED_HOSTS` должно содержать этот адрес без схемы и порта. `docker compose config` показывает итоговую конфигурацию, но не проверяет существование папок или доступность образа.

Для локальной сборки текущих исходников:

```bash
docker build -t mail-cloud-local:0.7.0 .
```

Затем укажите `MAILRU_IMAGE=mail-cloud-local:0.7.0` в `.env` и выполните:

```bash
docker compose up -d --pull never
```

Это локальная сборка. Она не публикует образ и не подключает его к обновлениям канала `stable`.

## Параметры Compose

| Параметр в `.env` | Назначение |
| --- | --- |
| `STATE_DIRECTORY` | Существующий абсолютный путь к локальной папке состояния; монтируется в `/state` с записью. |
| `PHOTO_LIBRARY` | Существующий абсолютный путь к фото и видео; монтируется в `/photos` только для чтения. |
| `PUID`, `PGID` | Значения поля `user` Docker; по умолчанию `1000:1000`. |
| `MAILRU_PORT` | Порт сервера, по умолчанию `31800`. |
| `MAILRU_ALLOWED_HOSTS` | Конкретные IP/DNS-имена панели через запятую, без схемы и порта. |
| `MAILRU_IMAGE` | Образ GHCR или локальный образ. |
| `MAILRU_PUBLIC_ORIGIN` | Необязательный внешний origin за reverse proxy; пустой при прямом LAN-доступе. |
| `MAILRU_TIMEZONE` | Исходный часовой пояс новых настроек, по умолчанию `Europe/Moscow`; впоследствии изменяется в панели. |

Не записывайте пароль приложения Mail или токены в `.env`. Вводите пароль в браузере.

## Запуск из исходников

Нужен Python 3.11 или новее. В корне репозитория:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[web]'
python -m mailru_photos.web --state /srv/mail-cloud-state --allow-root /srv/photos
```

Так панель слушает `127.0.0.1:8787`. Для прямого доступа в локальной сети укажите listen-адрес и разрешённое имя:

```bash
python -m mailru_photos.web \
  --host 0.0.0.0 \
  --port 31800 \
  --state /srv/mail-cloud-state \
  --allow-root /srv/photos \
  --allowed-host 192.168.1.10
```

Замените `/srv/...` своими путями, а примерный адрес `192.168.1.10` — адресом сервера. Здесь процесс читает пути Linux напрямую: это не пути контейнера. `--allow-root` и `--allowed-host` можно повторять. Встроенные разрешённые имена — `localhost`, `127.0.0.1` и `::1`.

## Первое открытие панели

Пароль панели создаётся при первом открытии. Задайте отдельный пароль длиной от 12 символов, затем:

1. **Аккаунт Mail.ru.** Введите адрес аккаунта и пароль внешнего приложения. Подключение проверяется на сервере.
2. **Исходные папки.** Добавьте доступную серверную папку, уникальное имя для списка и полный путь назначения в Облаке. В Docker исходник — `/photos` или его подпапки. Например, `/photos/family` → `/Archive/Family`.

Имя источника не добавляется к выбранному облачному пути. Глобального назначения в настройках панели больше нет. При обновлении старые пути каждого источника сохраняются.

Нажмите **«Начать загрузку»**. Приложение сканирует источники, если это необходимо, проверяет аккаунт и начинает обработку очереди. Контрольной загрузки и ожидания обновления квоты перед стартом нет.

Файлы передаются с сервера напрямую в Облако. Если вы открыли панель на ноутбуке, это не даёт контейнеру доступ к папкам ноутбука.

## Фото и видео

Сканер находит следующие расширения без учёта регистра:

- фото: `jpg`, `jpeg`, `png`, `heic`, `heif`, `webp`, `gif`, `raw`, `dng`, `tif`, `tiff`;
- видео: `mp4`, `3gp`, `3g2`, `3gpp`, `3gpp2`, `avi`, `vob`, `mov`, `mkv`, `m2t`, `m2ts`, `ts`, `mts`, `f4v`, `flv`, `wmv`, `m4v`, `mpg`, `ogv`, `webm`, `hevc`.

Обнаружение файла не означает, что он соответствует условиям безлимитной автозагрузки. [Справка Mail](https://help.mail.ru/cloud/files/autosave/) публикует такие сведения:

| Платформа | Фото | Видео |
| --- | --- | --- |
| Android | JPEG, PNG, WebP, RAW (DNG), HEIF | MP4, 3GP, MKV, WebM, AVI |
| iOS | HEIF, JPEG, RAW, TIFF, PNG, Live Photos | HEVC, H.264, Apple ProRes и режимы Cinematic, Slow-Motion, Time-Lapse |

В строке iOS указаны также кодеки и режимы съёмки, поэтому это не полная таблица расширений файлов. Клиент использует перечень как основу предварительной классификации. MOV добавлен в кандидаты по подтверждённой пользователем загрузке в его аккаунте; MP4 тоже проверен пользователем. Для каждого конкретного файла итог по-прежнему определяется ответом Облака.

**M4V в опубликованном перечне не указан.** Пользователь наблюдал расход квоты для M4V. Это не доказательство того, что Mail запрещает безлимит для любого файла с таким расширением, но клиент не обещает его: M4V и другие расширения вне подтверждённого списка планируются в обычное хранилище. Видео передаются без перекодирования и переименования расширения.

### Размер файла

Mail указывает предел автозагрузки **2 ГБ**, без точного количества байтов в справке. Клиент сохраняет протокольную границу Android-приложения **2 147 483 648 байт**. Более крупные файлы попадают в план обычной загрузки. [Условия автозагрузки](https://help.mail.ru/cloud/files/autosave/) и [описание безлимитной услуги](https://help.mail.ru/cloud/files/unlimited/).

В обычном режиме Mail заявляет до **100 ГБ** для пользователей подписки, но клиент проверяет лимит конкретного аккаунта и ответ сервера загрузки: доступ к услуге и фактический лимит нельзя определить только по расширению файла. [Справка об обычной загрузке](https://help.mail.ru/cloud/files/upload/).

## Политика хранения

В **Настройках → Использование места** доступны два независимых решения:

| Настройка | По умолчанию | Поведение |
| --- | --- | --- |
| Файлы, которым требуется место в квоте | Пропускать | При выборе «Загружать в квоту» неподходящие форматы и большие файлы отправляются обычным способом. Успешная проверка такого файла — успешная задача. |
| Если Облако не подтвердило безлимит | Переместить файл в корзину Облака | Для ожидавшегося безлимитного файла с явным отрицательным ответом можно выбрать корзину либо оставить объект. Задача в обоих случаях остаётся ошибочной, очередь продолжается. |

Клиент сверяет объект перед отправкой в корзину. Если результат хранения неизвестен, метаданные недоступны или объект изменился, он сохраняет ошибку; неизвестный результат не объявляется подтверждённым расходом квоты. Корзина не очищается автоматически.

После сканирования предупреждение показывает количество и размер файлов, которым нужно место, свободное место аккаунта и выбранную политику. Пока квота не получена, интерфейс пишет «неизвестно». В обзоре постоянно видны объёмы кандидатов в безлимит, задач с расходом квоты и уже размещённых объектов текущей очереди. Пропущенные по политике обычные файлы остаются в прогнозе, чтобы их объём был виден до изменения настройки.

## Управление источниками и повторное сканирование

В разделе **«Исходные папки»** у каждого источника есть **«Изменить»** и **«Убрать»**. Сначала приостановите текущую операцию и дождитесь её завершения.

Изменение облачного назначения применяется к новым задачам и задачам, которые ещё не отправлялись. Уже загруженные файлы и незавершённые подтверждения серверных операций сохраняют прежний облачный путь. Приложение не перемещает объекты в Облаке.

**«Убрать»** исключает источник и его задачи из приложения. Файлы на диске и в Облаке остаются. Подтверждения завершённых загрузок сохраняются отдельно от текущего списка задач.

Полное повторное сканирование обновляет очередь: отсутствующие файлы перестают учитываться в списке и прогрессе. Обычное перемещение внутри одного источника распознаётся по идентичности файла и сохраняет задачу, включая подтверждение завершённой загрузки. При неоднозначной идентичности, жёстких ссылках или незавершённом серверном запросе клиент не объединяет задачи наугад. Прерванное или ошибочное сканирование не объявляет непроверенные файлы исчезнувшими.

Общий процент показывает **обработанные задачи**: успешные, окончательно ошибочные и пропущенные. Ошибки, для которых ещё запланирована автоматическая повторная попытка, завершёнными не считаются. Число успешных загрузок и ошибок показывается отдельно; 100% обработки не означает, что каждая задача завершилась успешно.

## Пауза, продолжение и новые файлы

**«Приостановить»** сохраняет очередь и очищает запрос на автопродолжение. При остановке Docker без ручной паузы запрос на продолжение сохраняется; после запуска он учитывается, если включено **«Продолжать после перезапуска»**.

Автопродолжение не является постоянным наблюдением за папками. После добавления фото или видео в ранее просканированный каталог нажмите **«Пересканировать папки»**. Для повторения ошибочных заданий сначала устраните причину, затем используйте **«Повторить ошибки»**. Некоторые постоянные ошибки требуют отдельного решения.

В настройках можно выбрать от 1 до 16 параллельных загрузок; исходное значение панели — 2. Изменяйте настройки при остановленной операции.

Закрытие вкладки не останавливает сервер. Один каталог состояния должен использоваться только одним экземпляром панели или CLI; блокировки защищают очередь от конкурирующих процессов.

## Планировщик

Раздел **«Планировщик»** содержит независимые расписания. В каждом задаются название, одна или несколько исходных папок, время и повторение. Количество расписаний в интерфейсе не ограничено.

- **По дням недели:** выберите нужные дни. По умолчанию включены все семь.
- **По числам месяца:** перечислите числа через запятую, например `1, 15, 30`. Допустимы 1–30. Если числа в конкретном месяце нет, в этот день запуска не будет.
- Переключатель включает или выключает расписание, сохраняя остальные поля. Редактирование меняет будущие и ещё ожидающие запуски; текущую загрузку оно не прерывает.

В назначенное время клиент сначала сканирует только выбранные источники. После завершения обхода он выполняет их готовые задачи, включая вновь найденные файлы. Остальные источники этим запуском не сканируются и не загружаются. Ошибки отдельного файла обрабатываются так же, как при ручной загрузке.

Если другая операция уже идёт, сработавшее расписание сохраняется и ждёт освобождения клиента. Панель показывает это как ожидание очереди. При выключенном сервере пропущенные моменты не воспроизводятся задним числом; уже записанное срабатывание или сохранённый незавершённый запуск переживают перезапуск. При отсутствии входа в Mail срабатывание остаётся в ожидании авторизации. Общая пауза отменяет уже ожидающие срабатывания, но не выключает будущие расписания. Если выполнявшийся запуск расписания приостановлен, продолжение сохраняет выбранную им область источников.

Если **«Продолжать после перезапуска»** выключено, сохранённые ожидавшие и незавершённые срабатывания после запуска приложения остаются на паузе. Будущие расписания при этом сохраняют свои тумблеры и срабатывают в установленное время. Ручная пауза сохраняется при перезапуске. Удалённый источник исключается из области приостановленного запуска; остальные выбранные папки можно продолжить.

Все расписания используют **часовой пояс панели**, который виден над списком и меняется в **Настройках → Часовой пояс планировщика**. Принимаются имена IANA: `Europe/Moscow`, `Asia/Yekaterinburg`, `UTC` и другие из базы часовых поясов. В новой установке исходное значение — `Europe/Moscow`; переменная `MAILRU_TIMEZONE` задаёт другой исходный вариант. Сохранённое значение панели имеет приоритет над переменной окружения.

Часы браузера не определяют момент запуска. Даты ближайшего и последнего запуска отображаются в выбранном поясе. При сезонном переводе часов несуществующее локальное время пропускается, а повторяющийся час срабатывает один раз. Удаление всех источников расписания автоматически выключает его; выберите новые папки, чтобы включить снова.

Каждая карточка показывает ближайший запуск и состояние последнего: выполнение, завершение, очередь, паузу или ошибку с сообщением. Удаление расписания отменяет будущие и ещё ожидающие срабатывания, сохраняя уже созданные задачи и файлы. Для остановки выполняющейся операции используйте общую паузу.

## Управление задачами

Очередь показывает до 50 задач на странице. В одной строке находятся имя, процент передачи, размер, статус, время загрузки и действия. Полные пути и сообщение ошибки доступны при наведении на имя или статус. Сортировка **«Сначала старые / Сначала новые»** меняет порядок создания задач. Строка итогов под заголовками считает весь выбранный фильтр, а не только видимую страницу.

Вкладки **«Загружены в безлимит»** и **«Загружены в квоту»** определяются наблюдаемым результатом хранения. Поэтому файл, оставленный в обычном хранилище после неожиданного ответа сервера, виден и в квоте, и в ошибках. Неизвестный режим остаётся в общем списке с нейтральным статусом.

В меню **⋮**:

- **«Запустить»** начинает выбранную ожидающую или приостановленную задачу, даже если общая очередь на паузе. Остальные задачи от этого не запускаются.
- **«Остановить»** доступно работающей задаче и запрашивает остановку только её передачи.
- **«Повторить попытку»** заново запускает выбранную ошибочную задачу с обновлённым запасом попыток.
- **«Открыть»** показывает исходное фото в новой вкладке или скачивает неподдерживаемый браузером формат.
- **«В Облаке»** открывает частный адрес существующего облачного объекта. В браузере нужен вход в тот же Mail-аккаунт; публичная ссылка не создаётся.

100% передачи ещё не означает успешную проверку файла. Состояние задачи меняется после проверки результата. Ответ о принятом объекте сохраняется и при одновременной паузе: повторный запуск сверяет уже выполненную операцию. Возобновление не обещает продолжения HTTP-передачи с прежнего байта.

Обычная ошибка файла, отказ в чтении, конфликт имени, сбой проверки результата или изменение квоты не ставят всю очередь на паузу. Повторяемые сетевые сбои имеют ограниченные попытки. Отдельно обрабатываются потеря авторизации и невозможность надёжно сохранять состояние: без этих условий продолжать работу нельзя, причина показывается в общем статусе.

### Удаление задач и файлов

Корзина в строке и **«Очистить…»** открывают один диалог. Для очистки можно выбрать обработанные задачи, весь текущий фильтр или всю очередь. Перед действием сервер готовит подтверждение с количеством, размером и предупреждениями; смена выбора требует нового подсчёта.

Порядок вариантов:

1. **Задача из очереди** — выбрана всегда.
2. **Файл в Облаке** — дополнительно переместить в корзину Облака.
3. **Файл на диске сервера** — дополнительно удалить навсегда.

Для удаления исходников нужно ввести `УДАЛИТЬ С ДИСКА`. Клиент проверяет идентичность файла и не следует символическим ссылкам. Изменившийся исходник не удаляется. При частичном отказе ошибка остаётся видимой, вместо сообщения о полном успехе.

Задачу можно убрать во время загрузки; удаление физических файлов требует остановленной общей операции. По умолчанию `/photos` подключён только для чтения, поэтому удаление исходников недоступно. Чтобы разрешить его, измените **только photo mount** на `read_only: false` и выдайте процессу право записи/удаления в соответствующем dataset. `read_only: true` на уровне самого контейнера можно оставить. [Права на TrueNAS](TRUENAS_RU.md#удаление-исходников-с-диска).

Удаление только задач сохраняет исходники и облачные объекты. Источники остаются подключёнными, следующее ручное сканирование снова создаст задачи для найденных файлов. Обычное продолжение загрузки само по себе не выполняет повторное сканирование очищенной очереди.

### Открытие исходников

JPEG, PNG, WebP и GIF открываются в браузере; другие форматы выдаются как скачиваемый файл. Доступ требует входа в панель. Если исходник изменился после сканирования, сначала пересканируйте источник: содержимое старой задачи не заменяется новым файлом незаметно.

## Сверка с Облаком

Переключатель **«Проверять, есть ли файлы в Облаке»** выключен по умолчанию. Включайте его при остановленной операции и сохраняйте настройки. Затем пересканируйте источники.

Сверка проверяет точный путь назначения задачи. При совпавшем размере клиент вычисляет хеш исходника потоковым чтением, сравнивает его с облачным и повторно проверяет объект перед сохранением результата. Совпадение получает отдельную отметку **«Уже в Облаке»**. Оно не считается новой успешной загрузкой и не доказывает, что файл хранится без расхода квоты.

Проверка не ищет одинаковое содержимое по всем папкам аккаунта и не объединяет файлы только по имени. Разные облачные пути остаются разными назначениями. Для задач с незавершённой серверной операцией используется обычный механизм восстановления, а не предположение по совпадению хеша.

На большом архиве нужны запросы к серверу и чтение совпавших исходников, поэтому сканирование займёт больше времени. Пауза останавливает сверку. Ошибка дополнительной сверки сохраняется в событиях; завершённый локальный обход и уже сделанные наблюдения остаются. При общей сетевой ошибке сверка заканчивается досрочно, вместо повторения одного сбоя для каждой задачи. Отключение переключателя убирает этот этап из последующих сканирований.

Наблюдавшийся облачный путь защищён как путь уже завершённой задачи: перенос исходника или изменение назначения источника не изображают несуществующее перемещение в Облаке. Для намеренной новой загрузки по другому пути уберите задачу и пересканируйте источник. Изменившееся содержимое определяется обычным сканированием.

## Квота

В обзоре и меню аккаунта показываются занятое и доступное место; в обзоре также видны общий объём и время последнего измерения. Для общего пространства учитываются Почта и Облако; их объёмы показываются отдельно. Значения обновляются при входе, при проверках квоты во время загрузки и по кнопке обновления. При первом открытии панели после перезапуска выполняется начальное чтение, если аккаунт подключён и нет другой операции.

Во время работы браузер обновляет данные примерно раз в две секунды, в простое — раз в 30 секунд. Скрытая вкладка приостанавливает опрос. Неизменные данные сервер возвращает из кеша, без повторного открытия базы; опрос не запускает сканирование каталогов или запрос к Mail. Если чтение не удалось, последние значения остаются с предупреждением; они не заменяются нулями. Пока успешного измерения нет, объём показывается как неизвестный.

## Пароль панели

В настройках, в блоке **«Пароль панели»**, нажмите **«Сменить пароль»**, введите текущий пароль и дважды новый — от 12 символов. Сохраняется проверочное значение, а не открытый пароль. Текущая вкладка получает новый сеанс, остальные прежние сеансы перестают действовать. Авторизация Mail, источники и очередь не меняются.

Если пароль забыт, восстановление выполняется администратором сервера при **остановленной панели**. Незащищённого HTTP-сброса нет. В обычной установке из исходников:

```bash
python -m mailru_photos.web --state /srv/mail-cloud-state --reset-panel-password
```

Команда запрашивает новый пароль скрыто, дважды. В работающем приложении сброс отклоняется. Для Docker Compose сначала остановите сервис, затем запустите одноразовую команду с теми же mount и UID/GID:

```bash
docker compose stop mailru-photos
docker compose run --rm --no-deps --entrypoint python mailru-photos \
  -m mailru_photos.web --state /state --reset-panel-password
docker compose up -d
```

На NAS аналогичную команду можно выполнить из административного Shell TrueNAS, подключив существующий dataset `/state` к одноразовому контейнеру с тем же UID/GID. Не удаляйте папку состояния ради сброса пароля.

## Выход из Mail.ru

Нажмите на адрес аккаунта в правом верхнем углу и выберите **«Выйти из Mail.ru»**. Если сейчас идёт загрузка или сканирование, клиент сначала остановит работу с сохранением прогресса, затем удалит сохранённую авторизацию на этом сервере. Во время завершения отображается **«Выход из Mail.ru…»**; запуск новых операций временно недоступен.

Очередь, источники и история загрузок остаются. Чтобы продолжить работу, снова подключите тот же аккаунт: существующая очередь сохраняет свою привязку к нему. Выход отменяет автоматическое продолжение текущей загрузки, в том числе после перезапуска приложения.

**«Выйти из панели»** — отдельное действие. Оно завершает сессию браузера, а сервер продолжает ранее запущенную загрузку и сохраняет вход в Mail.

## Reverse proxy и HTTPS

Для прямого LAN-доступа достаточно `MAILRU_ALLOWED_HOSTS`. `MAILRU_PUBLIC_ORIGIN` при этом оставьте пустым.

Если TLS завершается на reverse proxy, задайте точный адрес, который пользователь открывает в браузере:

```yaml
environment:
  MAILRU_ALLOWED_HOSTS: "photos.example.com"
  MAILRU_PUBLIC_ORIGIN: "https://photos.example.com"
```

Настройте proxy на передачу исходного HTTP-заголовка `Host` к приложению. При нестандартном внешнем порте включите его в origin, например `https://photos.example.com:8443`. В `MAILRU_ALLOWED_HOSTS` порт по-прежнему не указывается. Размещайте панель в корне домена, без префикса пути.

Приложение проверяет точное совпадение `Origin` для изменяющих запросов и не использует произвольные forwarded-заголовки как источник публичного адреса. Если proxy передаёт другое имя в `Host`, его тоже необходимо явно разрешить; предпочтительнее сохранять исходное имя.

После установки публичного HTTPS origin пользуйтесь этим HTTPS-адресом. Прямой HTTP-вход по IP к тому же экземпляру больше не будет соответствовать origin и условиям cookie. Не отключайте проверки `Host`/`Origin` для устранения такой ошибки; исправьте адрес или proxy-конфигурацию.

HTTP в доверенной LAN не шифрует трафик браузера. Не публикуйте порт панели в интернете без настроенного защищённого доступа. Дополнительная авторизация или сетевые ограничения proxy выбираются по вашей инфраструктуре.

## Состояние и резервная копия

В `/state` находятся SQLite-очередь, сохранённая авторизация, настройки панели и служебная история. На Linux токены сохраняются в приватном файле; шифрование всего dataset при необходимости настраивается на уровне хранилища.

Перед резервным копированием остановите приложение и копируйте всю папку состояния. Снимок или копия одного файла `queue.sqlite3` во время работы не заменяет согласованную копию состояния. Не передавайте резервную копию другим людям и не добавляйте её в Git.

Для обычного Compose обновление опубликованного образа выполняется так:

```bash
docker compose stop
```

Сделайте резервную копию состояния, затем:

```bash
docker compose pull
docker compose up -d
```

В 0.5.0 база переходит на схему 2, в 0.5.1 — на схему 3, в 0.7.0 — на схему 4. Миграции автоматические и транзакционные. Более старые версии не открывают новую схему: для возврата нужен снимок `/state`, сделанный до соответствующего обновления.

Mount `/state` и внутренние пути источников должны сохраниться. Если в `.env` выбран фиксированный версионный тег, предварительно поменяйте его на нужный опубликованный выпуск.

## Диагностика

```bash
docker compose ps
docker compose logs --tail=100 mailru-photos
```

Журнал контейнера показывает краткие фазы работы и счётчики прогресса. Подробности заданий и ошибок смотрите в панели.

Для проверки HTTP с разрешённым адресом:

```bash
curl -fsS http://192.168.1.10:31800/healthz
```

`192.168.1.10` — пример; подставьте адрес своего сервера. Успешный `/healthz` подтверждает ответ веб-приложения, но не проверяет вход в Mail, доступность исходных файлов или успешность загрузки.

Ошибка `invalid_host` означает несовпадение имени в браузере и разрешённого списка. Ошибка `invalid_origin` обычно требует проверки схемы, имени, порта и `MAILRU_PUBLIC_ORIGIN`. Ошибка доступа к `/state` требует исправления UID/GID или ACL; запуск от root не нужен.

См. также [таблицу ошибок TrueNAS](TRUENAS_RU.md#если-приложение-не-запускается) и [CLI](CLI_RU.md).
