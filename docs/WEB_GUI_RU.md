# Браузерная панель

Для установки через интерфейс NAS используйте [инструкцию TrueNAS](TRUENAS_RU.md). Здесь описан обычный Docker Compose на Linux, запуск из исходников и настройка адреса панели.

## Docker Compose на Linux

1. Клонируйте репозиторий и скопируйте `.env.example` в `.env`.
2. Выберите отдельный локальный каталог состояния и существующую папку фотографий.
3. Замените в `.env` `STATE_DIRECTORY`, `PHOTO_LIBRARY`, `PUID`, `PGID` и `MAILRU_ALLOWED_HOSTS`.
4. Проверьте права каталогов, затем запустите контейнер.

Например, **для нового каталога состояния** на обычном Linux-сервере с UID/GID `1000:1000`:

```bash
sudo install -d -m 700 -o 1000 -g 1000 /srv/mail-cloud-state
```

Укажите `/srv/mail-cloud-state` как `STATE_DIRECTORY`. Для TrueNAS dataset создают и настраивают через его интерфейс. Существующее состояние не заменяйте пустым каталогом. Каталог фотографий и его родители должны разрешать выбранной паре UID/GID чтение и проход; mount остаётся только для чтения.

Запуск контейнера:

```bash
docker compose config
docker compose pull
docker compose up -d
docker compose logs --tail=100 mailru-photos
```

Пример `.env` публикует `31800:8787`. Откройте `http://АДРЕС_СЕРВЕРА:31800`; значение `MAILRU_ALLOWED_HOSTS` должно содержать этот адрес без схемы и порта. `docker compose config` показывает итоговую конфигурацию, но не проверяет существование папок или доступность образа.

Для локальной сборки текущих исходников:

```bash
docker build -t mail-cloud-local:0.4.2 .
```

Затем укажите `MAILRU_IMAGE=mail-cloud-local:0.4.2` в `.env` и выполните:

```bash
docker compose up -d --pull never
```

Это локальная сборка. Она не публикует образ и не подключает его к обновлениям канала `stable`.

## Параметры Compose

| Параметр в `.env` | Назначение |
| --- | --- |
| `STATE_DIRECTORY` | Существующий абсолютный путь к локальной папке состояния; монтируется в `/state` с записью. |
| `PHOTO_LIBRARY` | Существующий абсолютный путь к фотографиям; монтируется в `/photos` только для чтения. |
| `PUID`, `PGID` | Значения поля `user` Docker; по умолчанию `1000:1000`. |
| `MAILRU_PORT` | Порт сервера, по умолчанию `31800`. |
| `MAILRU_ALLOWED_HOSTS` | Конкретные IP/DNS-имена панели через запятую, без схемы и порта. |
| `MAILRU_IMAGE` | Образ GHCR или локальный образ. |
| `MAILRU_PUBLIC_ORIGIN` | Необязательный внешний origin за reverse proxy; пустой при прямом LAN-доступе. |

Не записывайте пароль приложения Mail или токены в `.env`. Вводите пароль в браузере.

## Запуск из исходников

Нужен Python 3.11 или новее. В корне репозитория:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[web]'
python -m mailru_photos.web --state /srv/mail-cloud-state --allow-root /srv/photos
```

Так панель слушает `127.0.0.1:8787`. Для прямого доступа в локальной сети укажите listen-адрес и разрешённое имя:

```bash
python -m mailru_photos.web \
  --host 0.0.0.0 \
  --port 31800 \
  --state /srv/mail-cloud-state \
  --allow-root /srv/photos \
  --allowed-host 192.168.1.10
```

Замените `/srv/...` своими путями, а примерный адрес `192.168.1.10` — адресом сервера. Здесь процесс читает пути Linux напрямую: это не пути контейнера. `--allow-root` и `--allowed-host` можно повторять. Встроенные разрешённые имена — `localhost`, `127.0.0.1` и `::1`.

## Первое открытие панели

Пароль панели создаётся при первом открытии. Задайте отдельный пароль длиной от 12 символов, затем выполните три шага в блоке первого запуска:

1. **Папка в Облаке.** Выберите новое назначение, например `/PhotoArchive`. Созданная очередь связана с этим назначением.
2. **Аккаунт Mail.ru.** Введите адрес аккаунта и пароль внешнего приложения. Подключение проверяется на сервере.
3. **Исходные фотографии.** Добавьте доступную серверную папку и уникальное имя источника. В Docker это `/photos` или его подпапки.

Нажмите **«Начать загрузку»**. Приложение сканирует источники, если это необходимо, проверяет аккаунт и начинает обработку очереди. При включённой предварительной проверке сначала выполняется контрольная загрузка с ожиданием измерений квоты.

Панель не загружает фотографии из браузера. Если вы открыли её на ноутбуке, это не даёт контейнеру доступ к папкам ноутбука.

## Предварительная проверка

В **Настройках** есть переключатель **«Предварительная проверка безлимита»**. По умолчанию он включён: перед массовой загрузкой клиент при необходимости загружает несколько контрольных файлов и ждёт обновления квоты.

Чтобы пропустить этот этап и ожидание, приостановите текущую операцию, выключите переключатель и нажмите **«Сохранить настройки»**. Выбор сохраняется после перезапуска и применяется к следующим запускам загрузки.

У каждого файла по-прежнему проверяются подтверждение безлимита от сервера, размер и хеш. Отсутствие подтверждения приостановит очередь; выключение предварительной проверки не включает обычную загрузку с расходованием квоты.

## Пауза, продолжение и новые файлы

**«Приостановить»** сохраняет очередь и очищает запрос на автопродолжение. При остановке Docker без ручной паузы запрос на продолжение сохраняется; после запуска он учитывается, если включено **«Продолжать после перезапуска»**.

Автопродолжение не является постоянным наблюдением за папками. После добавления фотографий в ранее просканированный каталог нажмите **«Найти новые файлы»**. Для повторения ошибочных заданий сначала устраните причину, затем используйте **«Повторить ошибки»**. Некоторые постоянные ошибки требуют отдельного решения.

В настройках можно выбрать от 1 до 16 параллельных загрузок; исходное значение панели — 2. Изменяйте настройки при остановленной операции.

Закрытие вкладки не останавливает сервер. Один каталог состояния должен использоваться только одним экземпляром панели или CLI; блокировки защищают очередь от конкурирующих процессов.

## Reverse proxy и HTTPS

Для прямого LAN-доступа достаточно `MAILRU_ALLOWED_HOSTS`. `MAILRU_PUBLIC_ORIGIN` при этом оставьте пустым.

Если TLS завершается на reverse proxy, задайте точный адрес, который пользователь открывает в браузере:

```yaml
environment:
  MAILRU_ALLOWED_HOSTS: "photos.example.com"
  MAILRU_PUBLIC_ORIGIN: "https://photos.example.com"
```

Настройте proxy на передачу исходного HTTP-заголовка `Host` к приложению. При нестандартном внешнем порте включите его в origin, например `https://photos.example.com:8443`. В `MAILRU_ALLOWED_HOSTS` порт по-прежнему не указывается. Размещайте панель в корне домена, без префикса пути.

Приложение проверяет точное совпадение `Origin` для изменяющих запросов и не использует произвольные forwarded-заголовки как источник публичного адреса. Если proxy передаёт другое имя в `Host`, его тоже необходимо явно разрешить; предпочтительнее сохранять исходное имя.

После установки публичного HTTPS origin пользуйтесь этим HTTPS-адресом. Прямой HTTP-вход по IP к тому же экземпляру больше не будет соответствовать origin и условиям cookie. Не отключайте проверки `Host`/`Origin` для устранения такой ошибки; исправьте адрес или proxy-конфигурацию.

HTTP в доверенной LAN не шифрует трафик браузера. Не публикуйте порт панели в интернете без настроенного защищённого доступа. Дополнительная авторизация или сетевые ограничения proxy выбираются по вашей инфраструктуре.

## Состояние и резервная копия

В `/state` находятся SQLite-очередь, сохранённая авторизация, настройки панели и служебная история. На Linux токены сохраняются в приватном файле; шифрование всего dataset при необходимости настраивается на уровне хранилища.

Перед резервным копированием остановите приложение и копируйте всю папку состояния. Снимок или копия одного файла `queue.sqlite3` во время работы не заменяет согласованную копию состояния. Не передавайте резервную копию другим людям и не добавляйте её в Git.

Для обычного Compose обновление опубликованного образа выполняется так:

```bash
docker compose stop
```

Сделайте резервную копию состояния, затем:

```bash
docker compose pull
docker compose up -d
```

Mount `/state` и внутренние пути источников должны сохраниться. Если в `.env` выбран фиксированный версионный тег, предварительно поменяйте его на нужный опубликованный выпуск.

## Диагностика

```bash
docker compose ps
docker compose logs --tail=100 mailru-photos
```

Журнал контейнера показывает краткие фазы работы и счётчики прогресса. Подробности заданий и ошибок смотрите в панели.

Для проверки HTTP с разрешённым адресом:

```bash
curl -fsS http://192.168.1.10:31800/healthz
```

`192.168.1.10` — пример; подставьте адрес своего сервера. Успешный `/healthz` подтверждает ответ веб-приложения, но не проверяет вход в Mail, доступность исходных файлов или успешность загрузки.

Ошибка `invalid_host` означает несовпадение имени в браузере и разрешённого списка. Ошибка `invalid_origin` обычно требует проверки схемы, имени, порта и `MAILRU_PUBLIC_ORIGIN`. Ошибка доступа к `/state` требует исправления UID/GID или ACL; запуск от root не нужен.

См. также [таблицу ошибок TrueNAS](TRUENAS_RU.md#если-приложение-не-запускается) и [CLI](CLI_RU.md).
