# План выпуска 0.7.0

Цель: после сканирования показывать план хранения, затем учитывать фактический результат каждой задачи. Пользователь управляет отдельными задачами и удалением, а ошибка файла не блокирует соседние задачи.

## Этапы и ответственность

1. **Правила хранения и модель очереди.** Сверить официальные форматы и ограничения. Отделить планируемый режим от наблюдаемого серверного результата, добавить объёмы, фильтры, сортировку и выбор задачи по ID. Миграция сохраняет историю; несовместимый старый код не должен писать в новую схему.
2. **Исполнение и ошибки.** Убрать контрольный файл и ожидание квоты. Разрешённая пользователем обычная загрузка — отдельный явный путь. Неожиданный отрицательный ответ о безлимите сохраняется до последующей проверки и очистки. По настройке оставить объект или отправить в корзину; задача остаётся ошибочной. Перезапуск не должен превращать такой ответ в успех.
3. **Управление и удаление.** Запуск выбранной задачи работает при остановленной общей очереди. Удаление всегда включает запись задачи; удаление облачного и локального исходника выбирается отдельно. Для физического удаления исходника нужны явное предупреждение, подтверждающая фраза, проверка идентичности и прав. Облачный объект удаляется только в корзину. Частичный отказ не скрывает незавершённые действия.
4. **Интерфейс.** Компактная строка задачи, меню действий, итоги по всему фильтру, две вкладки подтверждённого хранения и сортировка. На обзоре — планируемые и уже размещённые объёмы. После сканирования — предупреждение о расходе квоты. Настройки и меню аккаунта упрощаются по запросу.
5. **Кириллица и простой.** Проверить весь путь от имени каталога до JSON, URL, метаданных, скачивания и удаления. Кешировать неизменное состояние; опрос панели и healthcheck не должны регулярно открывать базу на HDD в простое.
6. **Планировщик.** Добавлен по уточнению пользователя: независимые расписания, несколько источников, время и дни недели либо числа месяца 1–30; перед каждой загрузкой — сканирование выбранных источников. Часовой пояс IANA задаётся в панели. Сработавшие ожидания сохраняются, пропущенное время при выключенном сервере не выполняется задним числом.
7. **TrueNAS и выпуск.** Проверить именно SCALE 24.10.2.3: метаданные Custom App, portal, реальные теги образов и проверку обновлений. Объяснить границы штатного YAML и отката базы. Обновить документацию, пройти регрессии и реальный контейнер, опубликовать 0.7.0 и обновить stable.

## Контракты

- Классификатор описывает план, а не гарантирует ответ Mail. Форматы из опубликованного перечня и допустимый размер — кандидаты на автозагрузку; остальные отправляются обычным способом только при включённой настройке.
- Фактические значения `unlimited`, `regular`, `unknown` отделены от статуса задачи. Принятый сервером объект может одновременно присутствовать в квоте и быть ошибочной задачей. Отсутствующий или некорректный флаг не трактуется как `false`.
- Повторное сканирование и переносы сохраняют привязку уже созданного облачного объекта к его фактическому адресу.
- По умолчанию обычная загрузка выключена; неожиданный отказ безлимита обрабатывается через корзину после проверки объекта. Эти настройки видимы и изменяемы.
- Ошибки файлов продолжают очередь. Невозможность авторизоваться или надёжно сохранять состояние требует отдельного общего сообщения; такие условия нельзя выдавать за успешную обработку.
- Удаление с диска не обходит read-only mount, ACL или защиту от символических ссылок. Исходник, изменившийся после выбора, не удаляется. В Облаке не очищается корзина.
- В простое данные интерфейса возвращаются из памяти. Изменения очереди, источников, настроек и операций инвалидируют кеш.

## Источники и ограничения

- [Mail: безлимитная автозагрузка](https://help.mail.ru/cloud/files/unlimited/)
- [Mail: обычная загрузка и ограничение файла](https://help.mail.ru/cloud/files/upload/)
- Точный формат M4V отсутствует в опубликованном перечне; это основание для осторожного планирования, но не доказательство универсального серверного запрета.
- MOV и MP4 подтверждены пользователем в его аккаунте. Новые автоматические тесты не подменяют эту живую проверку.

## Журнал

- Исходная версия: 0.6.0, коммит `87e9e48c1f4c54f9d49e0d0fa2d0944112acb052`; рабочая копия совпала с GitHub.
- Согласованы отдельные поля планируемого хранения и серверного наблюдения, агрегаты фильтров, API запуска одной задачи и двухэтапного удаления.
- Официальная справка публикует форматы Android, а для iOS также перечисляет кодеки и режимы съёмки. Полной гарантии классификации по одному расширению нет.
- Реализация разделена между очередью, интерфейсом и интеграцией; проведена независимая проверка API, планировщика, удаления и границ перезапуска.

- Интерфейс 0.7.0: компактные строки 43 px, 50 задач на странице, агрегаты по фильтру, запуск одного ID, наблюдаемые режимы, безопасный диалог удаления. Первый Chromium-прогон проверил desktop/mobile и отсутствие частого idle-опроса.
- CLI: контрольный файл и команда предварительной проверки убраны; добавлены явные политики хранения и `--job-id`. 24 проверки CLI прошли.
- Реальные исторические писатели баз 0.4.3, 0.4.4, 0.5.0, 0.5.1, 0.5.2 и 0.6.0 проверены с чтением схемой 4: сохранены задачи, паузы, подтверждения и история; rescan добавляет 0 задач, повторное открытие выполняет 0 записей. Результат в `validation/upgrade-history.json`.
- Планировщик подключён к UI и документирован; Docker включает IANA `tzdata`, начальная зона `Europe/Moscow`. Container smoke расширен кириллическими путями, новыми политиками, удалением через preview/token и сохранением расписаний после перезапуска.
- Финальный Chromium-прогон с реальными WebApplication/WebService/Queue/Scheduler и запрещённым Mail API прошёл: 37 HTTP-запросов, 12 сценариев, 0 ошибок JavaScript. Проверены кириллица, открытие исходника, weekly/monthly multi-source, валидация 1–30, timezone, обновление страницы, удаление расписания и массовое удаление задач через preview/token.
- Дополнительный Chromium-прогон с фиксированными ответами API прошёл 19 сценариев: продолжение локального удаления без Mail-аккаунта, отмена устаревшего preview, read-only защита, агрегаты всей выборки и адаптивный опрос. На экране 390 px нет переполнения страницы; таблица прокручивается внутри собственного контейнера.
- Автоматические копии перед миграцией проверены для всех шести исторических схем: исходная версия базы, история и подтверждения сохранены в самостоятельной SQLite-копии с журналом DELETE. После этих изменений все 24 проверки CLI прошли повторно.
- Benchmark 0.7.0 на 300 000 задачах завершён: максимальный наблюдавшийся RSS 32,65 МиБ, обе сортировки и режимы claim используют индексы, временной сортировки нет; 3 000 перемещений не создали дублей, 10 000 исчезновений исключены из текущих итогов. Отчёт: `validation/queue-300k-0.7.0.json`; измерения относятся к SQLite и виртуальным сведениям файлов, без сети.

- Интеграция: исправлены потери принятого запуска задачи при завершении работников, восстановление ручной паузы планировщика после сбоя и возобновление удаления после сетевого таймаута. Подтверждённый scan привязан к конкретному срабатыванию.
- Общий бюджет квоты сохраняется между работниками и дополнительными одиночными запусками. При известном недостатке места обычная передача не начинается; обработка остальных задач продолжается.
- Добавлен Python-пакет tzdata для установок web без системной IANA-базы; проверка установленного пакета использует пустой системный TZPATH.

- Итоговая локальная проверка установленного wheel: 543 теста приложения, 19 проверок публикации, миграции шести прежних версий и проверка установленных ресурсов/зависимостей прошли. Публикуемые файлы проверены Gitleaks без найденных секретов; README не содержит личного адреса сети, dataset или упоминаний безлимита. Настоящий контейнер является обязательным следующим gate CI.
