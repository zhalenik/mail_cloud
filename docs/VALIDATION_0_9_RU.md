# Проверка выпуска 0.9.0

Дата локальной проверки: 4 ноября 2026 года. Проверялись собранный и установленный wheel, настоящий HTTP-сервер панели, браузер Chromium и базы SQLite. Запросы в личный аккаунт Mail, отправка реальных писем и доступ к пользовательскому NAS не выполнялись.

## Проверки перед публикацией

| Проверка | Результат |
| --- | --- |
| Полный набор тестов установленного пакета с изолированным импортом | 757 тестов, успешно; 150,023 с |
| Метаданные wheel, ресурсы панели, команды CLI, резервная база часовых поясов | Успешно |
| Проверка установленных зависимостей `pip check` | Успешно |
| Обновление исторических баз до схемы 6 | 8 версий: 0.4.3, 0.4.4, 0.5.0, 0.5.1, 0.5.2, 0.6.0, 0.7.0, 0.8.0 |
| Защита неизменяемых релизов и порядка переключения stable | 19 тестов, успешно |
| Сценарии Chromium с изолированными ответами API | 24 проверки, успешно |
| Chromium с настоящим WebApplication/WebService, HTTP и SQLite | 14 проверок, успешно |

Локальное окружение: Linux x86_64, Python 3.12.14, SQLite 3.53.1, Chromium 151.0.7922.34. Тестовые реализации подменяли только внешние операции Облака и SMTP. Реальный HTTP-прогон проверял сохранение состояния, а не только верстку. Хеши проверенных файлов зафиксированы в JSON-отчётах; во время браузерных прогонов эти файлы не менялись.

В GitHub Actions установленные тесты и браузерные проверки являются обязательными условиями публикации. Затем workflow собирает настоящий Dockerfile, проверяет контейнер с обычным пользователем и отдельным UID/GID, подключённым состоянием, файловой системой контейнера только для чтения и перезапуском. Только после успешного завершения создаются версионный тег, образ и GitHub Release, а `stable` переключается на тот же digest. Локальные результаты в этом документе не подменяют отдельный журнал контейнерной проверки в Actions.

## Какие риски проверены

- Переход от одиночных исходных папок к группам сохраняет ID, очереди, пути назначения и повторяющиеся расписания. Обновление схемы создаёт самостоятельную резервную SQLite-копию с учётом WAL.
- Индивидуальное сканирование, запуск, повтор ошибок, экспорт и удаление задач ограничены выбранной группой. Будущие партии нельзя случайно запустить общей кнопкой обычных источников.
- Предварительный обход хранит каталоги и агрегаты, учитывает вложенные исключения и прямые файлы корня. Отмена построения не публикует частично рассчитанный план.
- Два предела партии проверяются одновременно; слишком большая папка остаётся отдельной. Календарь учитывает N × 24 часа, разрешённые дни, DST, пропущенные минуты, ручной запуск и перестановку.
- Незавершённая активация восстанавливается после перезапуска. Если начался откат, сохраняется намерение продолжить именно откат. Привязка до 200 источников выполняется одной транзакцией без полного пересчёта плана после каждой строки.
- Ручная пауза переживает перезапуск. Автопродолжение не захватывает задачи другого источника. Повтор ошибки завершённой партии получает новый идентификатор запуска, сохраняя успешные задачи.
- Очистка выбирает только подтверждённые создания конкретной партии. История создания остаётся доступна после удаления задач. Новый объект по тому же пути, даже с тем же содержимым, не получает старую принадлежность.
- Повторный запуск очистки после принятого облачного удаления и потерянной локальной отметки сверяет фактическое состояние. Уже записанный результат удаления не вызывает повторного запроса. Устаревший контекст партии после падения процесса не присваивается новым загрузкам из CLI.
- Очередь писем сохраняется на диске. Ошибки SMTP не меняют результат партии; пароль не возвращается через API. Проверены временные ошибки, отказ авторизации, изменение настроек во время отправки и частичный отказ получателей.
- В интерфейсе проверены кириллица, экранирование названий папок, ширина 390 px, перетаскивание и управление с клавиатуры. Выбранный источник вне первой страницы сохраняется; расписание удерживает выбранные ID при переходе между страницами и поиске.

## Обход 300 000 файлов

Использован настоящий локальный каталог: 300 000 записей файлов в 3 000 подпапках, суммарный логический размер 1 100 834 947 072 байта. Файлы разреженные и предназначены для проверки файловых атрибутов; это не настоящие фотографии и видео. Содержимое не читалось, сеть не использовалась.

| Операция | Измерение |
| --- | --- |
| Первый предварительный обход | 4,51 с |
| Повторный предварительный обход | 5,53 с |
| Распределение и календарь | 0,28 с, 45 партий |
| Максимальная память процесса теста, RSS | Около 27,8 МиБ |
| База предварительного обхода | 1 712 128 байт |
| База плана | 3 866 624 байта |
| 100 повторных чтений кешированных сводок в простое | 0 открытий SQLite |

Проверено, что каждый каталог назначен ровно один раз, суммы совпадают, ограничения соблюдены, отменённое построение не повреждает предыдущий результат, а базы проходят проверку целостности и повторное открытие.

Это измерение предварительного обхода и построения плана, не скорости загрузки и не потребления памяти всего приложения. Скорость HDD/NAS, чтения хешей и обхода Облака зависит от конкретного хранилища и соединения. Отчёт фиксирует хеши версии алгоритмов на момент измерения; последующие изменения восстановления, привязки источников и повторных запусков покрыты финальным набором тестов. Сам обход и алгоритм группировки после измерения не изменялись.

```bash

python -I scripts/check_package.py
python -I -m unittest discover -s tests -v
python scripts/check_upgrade.py
```
