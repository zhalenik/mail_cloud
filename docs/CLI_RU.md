# Работа через CLI

CLI использует тот же механизм очереди и загрузки, что и браузерная панель. Для NAS удобнее [панель](WEB_GUI_RU.md). Не запускайте два клиента с одним каталогом состояния одновременно.

## Установка

Нужен Python 3.11 или новее. В корне репозитория:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e .
python -m mailru_photos --help
```

Ниже `/srv/mail-cloud-state` и `/srv/photos` — примеры. В Windows используйте `py -3` вместо `python` и свои пути, заключая их в кавычки. Состояние храните на локальном диске вне сетевой или облачной синхронизации.

## Первый запуск

```bash
python -m mailru_photos --state /srv/mail-cloud-state init --destination /PhotoArchive
python -m mailru_photos --state /srv/mail-cloud-state login --email user@example.com
python -m mailru_photos --state /srv/mail-cloud-state doctor
python -m mailru_photos --state /srv/mail-cloud-state add-folder /srv/photos --alias Family --destination /Archive/Family
python -m mailru_photos --state /srv/mail-cloud-state scan
python -m mailru_photos --state /srv/mail-cloud-state status
python -m mailru_photos --state /srv/mail-cloud-state run --workers 2
```

`init` создаёт локальную очередь. `login` скрыто запрашивает пароль внешнего приложения Mail; пароль не передаётся аргументом командной строки. `doctor` показывает аккаунт, доступность режима загрузки и квоту, не отправляя файлы. Это необязательная диагностика.

`add-folder --destination` задаёт точный путь конкретного источника в Облаке. Без этого параметра используется `init destination` + `alias`. Вложенные пути сохраняются. `scan` заново составляет список задач по текущим исходникам и, когда вход сохранён, проверяет наличие файлов в Облаке. `run` обрабатывает сохранённую очередь. Контрольного файла и ожидания измерений квоты перед загрузкой больше нет.

После добавления файлов выполните `scan` ещё раз. `--extensions jpg,png,mp4,mov` задаёт фильтр, который сохраняется для следующих сканирований. Расширения не чувствительны к регистру; [список форматов](WEB_GUI_RU.md#фото-и-видео).

## Что делает повторное сканирование

Каждый `scan` удаляет прежние задачи из текущего списка и создаёт новые для файлов, которые сейчас есть в исходных папках. Номера задач изменяются; счётчик `added` показывает количество новых записей текущего прохода. Файлы на диске и в Облаке эта команда не удаляет. История результатов загрузки и подтверждения незавершённых попыток сохраняются отдельно.

При сохранённой авторизации `scan` получает свежий список доступных личных файлов Облака. Совпадение проверяется по размеру и полному хешу содержимого во всех прочитанных папках. Поэтому файл, перенесённый в другую облачную папку, получает состояние «Уже в облаке» с его фактическим путём. Файл, удалённый из Облака после предыдущей загрузки, снова остаётся ожидающей задачей. Признак хранения берётся из текущего ответа сервера; если его нет, режим отмечается как неизвестный.

Список Облака читается страницами по 500 объектов и хранится в отдельном SQLite-индексе. При первой сверке клиенту может понадобиться прочитать содержимое локальных файлов для хеширования. На Linux проверенные хеши повторно используются, пока путь, размер, время изменения и идентификаторы файла, включая `ctime`, остаются прежними. Сам список Облака при следующем `scan` запрашивается заново.

Без сохранённого входа команда выполняет только локальный обход. В `status` будут `local_complete: true`, `complete: true`, `cloud_checked: false` и `cloud_pending: true`. Это означает, что очередь составлена, а наличие файлов в Облаке ещё не проверено. После входа повторите `scan`; браузерная панель также выполнит недостающую сверку перед запуском загрузки, если проверка Облака включена в настройках.

Для намеренно локального прохода используйте:

```bash
python -m mailru_photos --state /srv/mail-cloud-state scan --local-only
```

`--local-only` не читает файл авторизации и не обращается к сети, даже если вход уже сохранён. При успешном обходе записывается `complete: true`, `cloud_checked: false`, `cloud_pending: false`. Задачи создаются по исходникам; статусы «Уже в облаке» в этом режиме не устанавливаются. Для последующей сверки выполните обычный `scan`.

Если авторизация сохранена, но вход или полная облачная сверка не удались, команда не подменяет результат успешным локальным проходом: `last_scan.complete` остаётся `false`. Неполный облачный индекс не используется для поиска совпадений. Уже собранная новая очередь сохраняется; после устранения причины повторите `scan`. Ошибка чтения отдельного исходного файла при сравнении записывается в его задачу, и проверка остальных файлов продолжается.

Коды завершения `scan`: `0` — выбранный проход завершён, `2` — обход или обязательная облачная сверка не завершены, `130` — остановка пользователем. В CLI предупреждение для браузерной панели после сканирования не создаётся.

## Политика хранения

По умолчанию `run` пропускает файлы, которым заведомо нужно место в обычном хранилище: форматы вне опубликованных условий автозагрузки и файлы больше допустимого размера. Разрешение указывается явно:

```bash
python -m mailru_photos --state /srv/mail-cloud-state run \
  --workers 2 \
  --regular-policy upload \
  --unexpected-unlimited-action keep
```

| Параметр | Значения | По умолчанию |
| --- | --- | --- |
| `--regular-policy` | `skip` — пропускать файлы с расходом квоты; `upload` — разрешить обычную загрузку. | `skip` |
| `--unexpected-unlimited-action` | `trash` — переместить подтверждённый обычный объект в корзину, если ожидался безлимит; `keep` — оставить его. | `trash` |
| `--workers` | От 1 до 16 одновременных загрузок. | `4` |
| `--max-attempts` | От 1 до 20 попыток для повторяемых ошибок. | `5` |
| `--job-id ID` | Обработать только выбранную задачу, в том числе остановленную или ошибочную. | Вся готовая очередь |

Параметры CLI задаются для конкретного запуска; настройки веб-панели они не изменяют. При неожиданном ответе о расходовании квоты задача остаётся ошибочной при любом выборе `trash`/`keep`. Разрешённая обычная загрузка при успешной проверке считается успешной задачей. Классификация до отправки — прогноз; итоговый режим подтверждает сервер.

Для отдельной задачи:

```bash
python -m mailru_photos --state /srv/mail-cloud-state run --job-id 42
```

Остальные задачи не запускаются. Передача продолжается с использованием сохранённых подтверждений; клиент не обещает продолжение HTTP-передачи с того же байта.

## Команды

| Команда | Назначение |
| --- | --- |
| `status` | Источники, последнее сканирование, счётчики и байты планируемого/наблюдаемого хранения. |
| `scan` | Заново собрать очередь; при сохранённом входе проверить текущие совпадения во всём личном Облаке. |
| `scan --local-only` | Заново собрать очередь без авторизации и сетевых запросов. |
| `run --workers 2` | Запустить готовую очередь. |
| `run --job-id 42` | Запустить одну задачу. |
| `update-folder ID --destination /New/Path` | Изменить назначение источника для будущих и незавершённых задач. |
| `remove-folder ID` | Убрать источник и задачи; файлы остаются на месте. |
| `errors --limit 20` | Показать задачи с ошибками и их ID. |
| `retry-failed --include-permanent` | Вернуть ошибки в очередь после устранения причины. |
| `recover` | Восстановить незавершённые задания после аварии, без сети. |
| `report --output report.json` | Сохранить диагностический отчёт без токенов. |

`--state` и `--quiet` указывайте до команды. Полный набор параметров: `python -m mailru_photos <команда> --help`.

Для остановки нажмите `Ctrl+C` и дождитесь завершения. Остановленный `scan` нужно повторить. После аварии `scan` сам восстанавливает незавершённые локальные задания перед пересозданием списка; команда `recover` доступна отдельно. Если нужно только продолжить сохранённую загрузку, используйте `run`. Не удаляйте состояние ради перезапуска. Диагностический отчёт содержит пути и сообщения ошибок: проверьте его перед публикацией.
