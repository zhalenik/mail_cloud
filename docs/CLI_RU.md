# Работа через CLI

CLI использует тот же механизм очереди и загрузки, что и браузерная панель. Для NAS удобнее [панель](WEB_GUI_RU.md). Не запускайте два клиента с одним каталогом состояния одновременно.

## Установка

Нужен Python 3.11 или новее. В корне репозитория:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e .
python -m mailru_photos --help
```

Ниже `/srv/mail-cloud-state` и `/srv/photos` — примеры. В Windows используйте `py -3` вместо `python` и свои пути, заключая их в кавычки. Состояние храните на локальном диске вне сетевой или облачной синхронизации.

## Первый запуск

```bash
python -m mailru_photos --state /srv/mail-cloud-state init --destination /PhotoArchive
python -m mailru_photos --state /srv/mail-cloud-state login --email user@example.com
python -m mailru_photos --state /srv/mail-cloud-state doctor
python -m mailru_photos --state /srv/mail-cloud-state add-folder /srv/photos --alias Family --destination /Archive/Family
python -m mailru_photos --state /srv/mail-cloud-state scan
python -m mailru_photos --state /srv/mail-cloud-state status
python -m mailru_photos --state /srv/mail-cloud-state run --workers 2
```

`init` создаёт локальную очередь. `login` скрыто запрашивает пароль внешнего приложения Mail; пароль не передаётся аргументом командной строки. `doctor` показывает аккаунт, доступность режима загрузки и квоту, не отправляя файлы. Это необязательная диагностика.

`add-folder --destination` задаёт точный путь конкретного источника в Облаке. Без этого параметра используется `init destination` + `alias`. Вложенные пути сохраняются. `scan` находит файлы, обновляет существующие задачи и учитывает исчезнувшие исходники. `run` обрабатывает сохранённую очередь. Контрольного файла и ожидания измерений квоты перед загрузкой больше нет.

После добавления файлов выполните `scan` ещё раз. `--extensions jpg,png,mp4,mov` задаёт фильтр, который сохраняется для следующих сканирований. Расширения не чувствительны к регистру; [список форматов](WEB_GUI_RU.md#фото-и-видео).

## Политика хранения

По умолчанию `run` пропускает файлы, которым заведомо нужно место в обычном хранилище: форматы вне опубликованных условий автозагрузки и файлы больше допустимого размера. Разрешение указывается явно:

```bash
python -m mailru_photos --state /srv/mail-cloud-state run \
  --workers 2 \
  --regular-policy upload \
  --unexpected-unlimited-action keep
```

| Параметр | Значения | По умолчанию |
| --- | --- | --- |
| `--regular-policy` | `skip` — пропускать файлы с расходом квоты; `upload` — разрешить обычную загрузку. | `skip` |
| `--unexpected-unlimited-action` | `trash` — переместить подтверждённый обычный объект в корзину, если ожидался безлимит; `keep` — оставить его. | `trash` |
| `--workers` | От 1 до 16 одновременных загрузок. | `4` |
| `--max-attempts` | От 1 до 20 попыток для повторяемых ошибок. | `5` |
| `--job-id ID` | Обработать только выбранную задачу, в том числе остановленную или ошибочную. | Вся готовая очередь |

Параметры CLI задаются для конкретного запуска; настройки веб-панели они не изменяют. При неожиданном ответе о расходовании квоты задача остаётся ошибочной при любом выборе `trash`/`keep`. Разрешённая обычная загрузка при успешной проверке считается успешной задачей. Классификация до отправки — прогноз; итоговый режим подтверждает сервер.

Для отдельной задачи:

```bash
python -m mailru_photos --state /srv/mail-cloud-state run --job-id 42
```

Остальные задачи не запускаются. Передача продолжается с использованием сохранённых подтверждений; клиент не обещает продолжение HTTP-передачи с того же байта.

## Команды

| Команда | Назначение |
| --- | --- |
| `status` | Источники, последнее сканирование, счётчики и байты планируемого/наблюдаемого хранения. |
| `scan` | Обновить очередь по исходникам. |
| `run --workers 2` | Запустить готовую очередь. |
| `run --job-id 42` | Запустить одну задачу. |
| `update-folder ID --destination /New/Path` | Изменить назначение источника для будущих и незавершённых задач. |
| `remove-folder ID` | Убрать источник и задачи; файлы остаются на месте. |
| `errors --limit 20` | Показать задачи с ошибками и их ID. |
| `retry-failed --include-permanent` | Вернуть ошибки в очередь после устранения причины. |
| `recover` | Восстановить незавершённые задания после аварии, без сети. |
| `report --output report.json` | Сохранить диагностический отчёт без токенов. |

`--state` и `--quiet` указывайте до команды. Полный набор параметров: `python -m mailru_photos <команда> --help`.

Для остановки нажмите `Ctrl+C` и дождитесь завершения. При аварии используйте `recover`, затем повторите `scan` при изменении исходников и `run`. Не удаляйте состояние ради перезапуска. Диагностический отчёт содержит пути и сообщения ошибок: проверьте его перед публикацией.
