# План выпуска 0.8.0

Цель: новое сканирование отражает текущее состояние исходников и Облака. Старые результаты задач не подменяют проверку наличия файла; совпадение в другой папке Облака тоже учитывается.

## Этапы

1. **Протокол и облачный список.** Исправить обработку успешного обычного commit с неполным дополнительным блоком метаданных. Завершать задачу только после проверки созданного объекта. Добавить постраничное чтение личных каталогов Облака с проверкой полноты ответа.
2. **Новая очередь сканирования.** Пересоздавать задачи выбранных источников, сохраняя отдельную историю и сведения о незавершённых запросах создания. Новые ID не повторяются. Историческое подтверждение не является текущим подтверждением присутствия объекта.
3. **Сверка по содержимому.** Создавать свежий SQLite-индекс облачных файлов, искать по размеру и хешу независимо от пути. Сохранять фактический адрес и известный режим хранения; неизвестный режим показывать явно. Кешировать только локальные хеши неизменённых исходников, не облачное присутствие.
4. **Управление задачами.** Добавить пропуск и возврат в очередь, сохранённый прогресс, дату создания и дату завершения. Сортировать весь выбранный набор на сервере по каждому столбцу. Экспортировать TXT/CSV потоком с выбранными фильтрами, колонками, разделителем и заголовком.
5. **Интерфейс.** Действие открытия на имени, действия задачи на статусе, отдельная кнопка удаления. Цвета и подсказки отражают совпадение пути и режим хранения. Добавить управление общей загрузкой и сканированием в очередь, размер страницы, новые сводки и общий статус приложения.
6. **Интеграция и выпуск.** Подавлять предупреждение о квоте для найденных объектов и срабатываний планировщика. Проверить миграцию, отмену и перезапуск, большие очереди и браузер. Публиковать 0.8.0 и stable после проверки настоящего контейнера.

## Решения и ограничения

- Пересоздание списка не удаляет файлы на сервере или в Облаке. При выборочном расписании обновляются только выбранные источники.
- Неопределённый запрос создания хранится отдельно, чтобы пересканирование не потеряло возможность безопасного восстановления после сбоя.
- Для подтверждения совпадения требуются размер и хеш; имя само по себе не подходит.
- Облачный список перечитывается при каждом включённом проходе сверки. Неполный ответ не доказывает отсутствие файлов. Параллельные изменения другим клиентом не образуют атомарный снимок средствами этого протокола.
- Процент на паузе — сохранённый достигнутый прогресс; он не обещает неподтверждённую поддержку возобновления сетевого потока с произвольного байта.
- Проверки выполняются без пользовательского аккаунта Mail. Публикуемый репозиторий не содержит авторизации, личных путей или адресов сервера.

## Журнал

- База работы: 0.7.0, коммит `0f0edc7a838a016e11814207d709e899fec303b2`. Рабочая копия и main совпадают.
- Согласованы контракты сортировки, потокового экспорта, сохранённого прогресса и постраничной инвентаризации.
- Установлено, что обычный commit сейчас требует полный дополнительный пакет даже после успешного status=0. Точного ответа пользовательского сервера нет; исправление проверяется вариантами протокольных ответов и отдельной проверкой объекта.
