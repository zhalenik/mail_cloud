# mail_cloud

Загрузчик фотографий в Облако Mail с управлением через браузер. Работает на сервере или NAS: выбираете папки, запускаете загрузку и следите за очередью. Вкладку можно закрыть — файлы продолжат загружаться.

Приложение сохраняет структуру папок, показывает прогресс и ошибки, умеет ставить загрузку на паузу и продолжать после перезапуска. Исходные фотографии не изменяются.

Поддерживаются фотографии с расширениями `jpg`, `jpeg`, `png`, `heic`, `heif`, `webp` и `gif`. Видео не загружаются. Это неофициальный клиент; для входа нужен аккаунт Mail и пароль внешнего приложения с доступом к Облаку.

## Установка на TrueNAS

Подходит для **TrueNAS SCALE 24.10 и новее**, где приложения работают через Docker. Готовый образ рассчитан на Intel/AMD (`linux/amd64`), вход в GitHub для скачивания не нужен.

1. Создайте отдельный dataset для состояния приложения. Определите каталог с фотографиями.
2. Откройте [deploy/truenas-compose.yaml](deploy/truenas-compose.yaml). Замените два пути `/mnt/CHANGE_ME/...` на свои и укажите адрес NAS в `MAILRU_ALLOWED_HOSTS`.
3. Проверьте `user: "1000:1000"`: выбранному UID/GID нужны запись в dataset состояния и чтение фотографий. Для пользователя TrueNAS `apps` можно указать `568:568`, выдав ему эти права.
4. В **Apps → Discover Apps → ⋮ → Install via YAML** задайте имя `mail-cloud`, вставьте YAML и сохраните.
5. Дождитесь запуска и откройте `http://<адрес-NAS>:31800`.

Порт в шаблоне — `31800:8787`. В `MAILRU_ALLOWED_HOSTS` нужен IP или DNS-адрес NAS без `http://` и порта; это настройка доступа к панели, а не привязка Docker к сетевому интерфейсу.

[Подробная инструкция TrueNAS](docs/TRUENAS_RU.md) описывает права, подключение нескольких dataset и возможные ошибки запуска.

## Установка через Docker Compose

Для обычного Linux-сервера:

```bash
git clone https://github.com/zhalenik/mail_cloud.git
cd mail_cloud
cp .env.example .env
```

В `.env` укажите существующие каталоги `STATE_DIRECTORY` и `PHOTO_LIBRARY`, UID/GID пользователя контейнера и адрес сервера в `MAILRU_ALLOWED_HOSTS`. Затем запустите:

```bash
docker compose config
docker compose pull
docker compose up -d
```

Панель будет доступна по адресу `http://<адрес-сервера>:31800`.

## Первый запуск

При первом открытии задайте пароль панели длиной от 12 символов. Это отдельный пароль, не пароль Mail.

В панели выберите папку назначения в Облаке, подключите аккаунт Mail и добавьте источник фотографий. В стандартном контейнере это `/photos` или его подпапки. Если панель открыта с другого компьютера, в ней всё равно выбираются папки сервера.

Каждому источнику задаётся короткое имя. Например, при назначении `/PhotoArchive` и имени `Family` файл `/photos/2024/photo.jpg` попадёт в `/PhotoArchive/Family/2024/photo.jpg`.

Нажмите **«Начать загрузку»**. Клиент сам просканирует папки и создаст очередь. В ней видны текущие задания, завершённые файлы и ошибки.

- **«Приостановить»** останавливает загрузку с сохранением прогресса.
- **«Продолжить загрузку»** возвращает в работу незавершённые задания.
- **«Найти новые файлы»** обновляет очередь после добавления фотографий в исходные папки. Постоянного наблюдения за каталогами нет.

В настройках можно выбрать число одновременных загрузок и включить продолжение после перезапуска. По умолчанию загружаются два файла одновременно. Ручная пауза сохраняется и после перезапуска.

## Обновление

`ghcr.io/zhalenik/mail_cloud:stable` — образ с обновлениями. Для выбора определённой версии используйте её тег, например `ghcr.io/zhalenik/mail_cloud:v0.4.2`. [Список выпусков](https://github.com/zhalenik/mail_cloud/releases) и [история изменений](CHANGELOG.md).

В TrueNAS обновите приложение через **Apps → Installed → ⋮ → Update**. Если в YAML указан номер версии, сначала замените его на нужный тег.

Очередь, настройки и вход в Mail хранятся в `/state`. Перед обновлением приостановите загрузку, остановите приложение и сделайте снимок dataset состояния. Сохраните тот же dataset, UID/GID и пути источников внутри контейнера — тогда новая версия продолжит работу с существующей очередью.

Для Docker Compose после резервной копии состояния выполните `docker compose pull` и `docker compose up -d`.

Панель предназначена для локальной сети. Для доступа извне настройте HTTPS или VPN. В `/state` находятся токены аккаунта: храните этот каталог отдельно от общих сетевых папок и не добавляйте его в репозиторий.

Об ошибках можно написать в [Issues](https://github.com/zhalenik/mail_cloud/issues). Укажите версию приложения и текст ошибки; пароли, токены и папку состояния прикладывать не нужно.
