# mail_cloud

Загрузчик фотографий и видео в Облако Mail. Работает на Linux-сервере или NAS, управляется через браузер и сохраняет очередь после перезапуска. Файлы передаются с сервера напрямую в Облако.

Можно объединить несколько каталогов в один источник, назначить ему папку в Облаке и загружать архив с сохранением вложенной структуры. В очереди видны прогресс, размер, результат, время создания и завершения задачи. Отдельную задачу можно запустить, остановить, пропустить или повторить. Ошибка одного файла не мешает остальным.

Панель показывает свободное место аккаунта и объём текущих задач. После сканирования она предупреждает о файлах, которые займут место. Их можно пропускать или разрешить загрузку в настройках. Подробности форматов и режимов — в [руководстве панели](docs/WEB_GUI_RU.md#фото-и-видео).

Это неофициальный клиент. Для входа нужен аккаунт Mail и пароль внешнего приложения с доступом к Облаку.

## TrueNAS SCALE

Шаблон подходит для Docker Apps в **SCALE 24.10 и новее**. Готовый образ — `linux/amd64`, для компьютеров Intel и AMD. Скачать его можно без входа в GitHub.

1. Создайте отдельный dataset для состояния приложения и выберите папку с архивом.
2. Откройте [deploy/truenas-compose.yaml](deploy/truenas-compose.yaml). Замените пути `CHANGE_ME`, укажите адрес NAS в `MAILRU_ALLOWED_HOSTS` и подходящий UID/GID в `user`.
3. Дайте этому UID/GID право записи в dataset состояния и чтения исходников.
4. В **Apps → Discover Apps → ⋮ → Install via YAML** задайте имя приложения и вставьте YAML.
5. Откройте `http://<адрес-NAS>:31800`.

Docker публикует порт `31800:8787`. `MAILRU_ALLOWED_HOSTS` содержит IP или DNS-имя сервера без схемы и порта: приложение использует его для проверки адреса входящего запроса.

[Инструкция TrueNAS](docs/TRUENAS_RU.md) объясняет настройки прав, кнопку Web UI, обновления и откат. В карточке Custom App TrueNAS может показывать `custom` и `1.0.0`; версию клиента смотрите в самой панели.

## Docker Compose

Для обычного Linux-сервера:

```bash
git clone https://github.com/zhalenik/mail_cloud.git
cd mail_cloud
cp .env.example .env
```

В `.env` укажите `STATE_DIRECTORY`, `PHOTO_LIBRARY`, UID/GID и адрес сервера в `MAILRU_ALLOWED_HOSTS`. Оба каталога должны уже существовать. Затем:

```bash
docker compose config
docker compose pull
docker compose up -d
```

Адрес панели — `http://<адрес-сервера>:31800`. [Запуск из исходников и настройка HTTPS](docs/WEB_GUI_RU.md).

## Работа с архивом

При первом открытии задайте пароль панели от 12 символов. Подключите Mail через меню аккаунта справа вверху, затем добавьте исходные папки. В стандартном контейнере они доступны через `/photos`.

Для каждого источника задайте полный путь в Облаке. Например, при назначении `/Archive/Family` исходник `/photos/2024/photo.jpg` попадёт в `/Archive/Family/2024/photo.jpg`. Имя источника служит подписью в панели и не добавляется к этому пути.

Нажмите **«Начать загрузку»**. Клиент выполнит нужное сканирование и начнёт обработку. После изменения файлов нажмите **«Пересканировать папки»**: постоянного обхода каталогов нет. Каждый проход заново собирает задачи выбранных источников. С включённой сверкой клиент читает актуальный список Облака и ищет совпадения по содержимому во всех личных папках, даже если файл был перемещён. Удалённый из Облака файл снова становится задачей загрузки.

Нажатие на имя открывает исходник в новой вкладке или скачивает его. Статус завершённой задачи ведёт к объекту в Облаке; статус ожидающей, остановленной или ошибочной задачи открывает доступные действия. **«Запустить»** начинает выбранную задачу даже при общей паузе. Сортировка работает по заголовкам столбцов, на странице можно показывать 25–200 записей. Строка итогов считает весь выбранный фильтр, а список можно скачать в TXT или CSV.

Пересканирование заменяет задачи, включая их индивидуальные паузы и ручные пропуски. Файлы при этом не удаляются. Если нужно продолжить прежнюю очередь, используйте **«Продолжить»**, а не пересканирование. Сверка включена при новой установке; ранее сохранённое отключение остаётся в силе. Большой архив проверяется постранично, индекс хранится на диске. Повторные проходы используют кеш хешей неизменённых исходников, но перечитывают список Облака.

При удалении можно убрать только задачу, дополнительно отправить облачный файл в корзину или удалить исходник с диска. Последний вариант требует отдельного подтверждения и права записи в исходную папку. По умолчанию Docker подключает фотоархив только для чтения.

Настройки, очередь и авторизация хранятся в `/state`. Ручная пауза сохраняется после перезапуска. Если разрешено автопродолжение, загрузка, работавшая до остановки сервера, возобновится. Выход из панели не останавливает сервер; выход из Mail останавливает работу и удаляет сохранённую авторизацию.

## Загрузка по расписанию

В **«Планировщике»** можно создать несколько расписаний: выбрать исходные папки, время, дни недели или числа месяца 1–30. Каждый запуск сначала сканирует выбранные источники, затем загружает их готовые задачи. Если клиент занят, запуск ждёт своей очереди. Время считается в часовом поясе панели, который меняется в настройках; пропущенные моменты при выключенном сервере не запускаются задним числом.

## План большого архива

**«План загрузки»** помогает перенести архив постепенно. Выберите корневой каталог: клиент подсчитает фото и видео по папкам, покажет дерево и позволит исключить ненужные ветки. На этом шаге содержимое файлов не читается и запросы в Облако не отправляются.

Задайте желаемое число файлов и объём на партию, допустимое превышение, дату начала, время, интервал в сутках и дни недели. Клиент предложит партии и календарь. Подпапки первого уровня сохраняются целиком; слишком большая папка получает отдельную партию с предупреждением. Порядок и будущие даты можно изменить до запуска.

После активации для партий создаются составные источники. Каждая партия однократно сканирует свои каталоги и загружает очередь; следующая ждёт её завершения. Остановка, продолжение и ручной запуск доступны в таблице плана. При задержке календарь пересчитывается. Повторяющиеся расписания остаются в отдельном разделе.

Уведомления о завершении партии, ошибках и завершении плана настраиваются в **«Настройки → Уведомления email»**. Для SMTP нужен отдельный пароль с разрешением отправлять почту. Сохранение настроек само по себе письмо не отправляет; для проверки есть кнопка тестового письма.

## Обновление и возврат к предыдущей версии

Для канала обновлений оставьте в YAML:

```yaml
image: ghcr.io/zhalenik/mail_cloud:stable
pull_policy: always
```

В TrueNAS включите **Apps → Configuration → Settings → Check for docker image updates**. На 24.10 проверка registry выполняется по расписанию; индикатор обновления может появиться не сразу. Для обновления без ожидания: приостановите загрузку, остановите приложение, сделайте снимок dataset состояния и запустите приложение снова. `pull_policy: always` проверит образ при развёртывании. [Подробности](docs/TRUENAS_RU.md#обновление).

Для фиксации выпуска укажите, например, `ghcr.io/zhalenik/mail_cloud:v0.9.0`. Версионный тег не переключается на следующие выпуски автоматически.

**В 0.9.0 база обновляется до схемы 6.** Перед переходом сохраните снимок всего dataset состояния при остановленном приложении. Для отката на 0.8.0 или более раннюю версию нужны и прежний образ, и снимок состояния до обновления. Сохраняйте пути `/state`, `/photos/...` и UID/GID. Старые источники, задачи и повторяющиеся расписания переносятся автоматически.
