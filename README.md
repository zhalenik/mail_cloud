# mail_cloud — фотоархив для Облака Mail

Браузерная панель для загрузки собственных фотографий с сервера или NAS в Облако Mail. Клиент сохраняет структуру папок и очередь на диске, показывает прогресс, позволяет приостановить работу и продолжить её после перезапуска.

Это независимый экспериментальный проект. Для загрузки требуется аккаунт Mail с доступным режимом безлимитной автозагрузки фотографий. Перед массовой передачей клиент выполняет контрольную загрузку, затем проверяет подтверждение режима хранения, размер и хеш файлов. Успешная проверка — результат наблюдения в момент запуска, а не гарантия будущего поведения сервиса.

**Версия исходников: 0.4.1.** Первая публикация Docker-образа в GHCR ещё должна успешно завершиться; наличие файлов сборки само по себе не означает, что образ уже доступен. Статус смотрите в [GitHub Actions](https://github.com/zhalenik/mail_cloud/actions) и [релизах](https://github.com/zhalenik/mail_cloud/releases).

## Что умеет

- Загружать несколько папок и сохранять их вложенную структуру.
- Хранить очередь и результаты проверок в SQLite.
- Показывать общий прогресс, текущие файлы и ошибки в браузере.
- Продолжать ранее запущенную загрузку после перезапуска, если включено автопродолжение.
- Читать исходные фотографии через Docker mount только для чтения.
- Работать через CLI, если браузерная панель не нужна.

По умолчанию обнаруживаются `jpg`, `jpeg`, `png`, `heic`, `heif`, `webp` и `gif`. Наличие расширения в этом списке не гарантирует, что Облако примет конкретный файл в безлимитном режиме. Видео и произвольные файлы в этот сценарий не входят.

## Установка на TrueNAS

Нужен TrueNAS с **Docker Apps: SCALE 24.10 или новее**. Для старых выпусков на Kubernetes этот Compose-файл не подходит. [Версионная справка TrueNAS](https://www.truenas.com/docs/scale/24.10/scaleuireference/apps/).

1. Подготовьте отдельный локальный dataset для состояния приложения и определите папку с фотографиями. Образ по умолчанию работает с UID/GID `1000:1000`: этому пользователю нужны запись в состоянии и чтение фотографий.
2. Откройте [deploy/truenas-compose.yaml](deploy/truenas-compose.yaml). Замените **оба** пути `/mnt/CHANGE_ME/...` на существующие пути вашего NAS. При необходимости измените UID/GID и адрес в `MAILRU_ALLOWED_HOSTS`.
3. После успешной публикации образа откройте **Apps → Discover Apps → ⋮ → Install via YAML**, задайте имя `mail-cloud` и вставьте YAML.
4. Сохраните приложение и дождитесь запуска.
5. Откройте **[http://192.168.68.106:31800](http://192.168.68.106:31800)**. Если у NAS другой адрес, используйте его. Установка через YAML не добавляет кнопку Web UI — прямой адрес работает независимо от неё.
6. Создайте пароль панели, настройте папку в Облаке, подключите аккаунт Mail и выберите исходную папку `/photos`. Нажмите **«Начать загрузку»**.

[Подробная инструкция TrueNAS: права, несколько папок, обновления и диагностика →](docs/TRUENAS_RU.md)

## Порт и адрес панели

В примере используется обычная публикация порта:

```yaml
ports:
  - "31800:8787"
environment:
  MAILRU_ALLOWED_HOSTS: "192.168.68.106"
```

`31800` — порт NAS, `8787` — порт приложения внутри контейнера. IP в `ports` не нужен. `MAILRU_ALLOWED_HOSTS` разрешает HTTP-заголовок `Host` и защищает панель от запросов через посторонние имена, в том числе DNS rebinding; эта настройка **не привязывает Docker к IP-адресу**. Указывайте конкретный адрес или имя, без `http://` и без порта. Для нескольких имён используйте запятые.

При прямом доступе из локальной сети `MAILRU_PUBLIC_ORIGIN` задавать не нужно: приложение берёт origin из текущего запроса, включая порт. Эта переменная предназначена для внешнего адреса за reverse proxy; пример есть в [инструкции панели](docs/WEB_GUI_RU.md#reverse-proxy-и-https).

## Обычный Docker Compose

Для Linux-сервера с Docker Compose:

```bash
git clone https://github.com/zhalenik/mail_cloud.git
cd mail_cloud
cp .env.example .env
```

В `.env` замените `STATE_DIRECTORY`, `PHOTO_LIBRARY`, UID/GID и адрес панели. Оба каталога должны уже существовать. Затем, после публикации образа:

```bash
docker compose config
docker compose pull
docker compose up -d
```

Откройте `http://АДРЕС_СЕРВЕРА:31800`. [Подготовка каталогов и локальная сборка →](docs/WEB_GUI_RU.md)

## Как пользоваться

Пароль панели и пароль приложения Mail — разные данные. Сначала задайте отдельный пароль панели длиной от 12 символов. Затем выберите папку назначения, например `/PhotoArchive`, подключите Mail с паролем внешнего приложения и добавьте источник с коротким уникальным именем, например `Family`.

При таком выборе файл `/photos/2024/photo.jpg` попадёт в `/PhotoArchive/Family/2024/photo.jpg`. В браузере выбираются папки **сервера**, доступные контейнеру; файлы с компьютера, на котором открыт браузер, автоматически не передаются.

**«Начать загрузку»** при необходимости найдёт фотографии и выполнит контрольную проверку. **«Приостановить»** сохраняет очередь. Для файлов, добавленных в уже просканированные папки, нажмите **«Найти новые файлы»**, затем продолжите загрузку. Постоянного наблюдения за каталогами нет.

## Обновления и сохранность очереди

`ghcr.io/zhalenik/mail_cloud:stable` — канал обновлений; `ghcr.io/zhalenik/mail_cloud:v0.4.1` — выбор конкретного выпуска. TrueNAS отслеживает обновление образа и предлагает действие **Update**; установка обновления выполняется вручную. Подробности и различия версионных тегов: [обновление TrueNAS](docs/TRUENAS_RU.md#обновление).

Очередь, авторизация и настройки находятся в `/state`. При обновлении сохраняйте тот же dataset, UID/GID и пути источников внутри контейнера. Перед сменой версии остановите приложение и сделайте снимок dataset состояния. Обычная замена контейнера с тем же bind mount сохраняет эти данные.

Автоматический перенос существующей Windows-очереди на Linux/TrueNAS пока не реализован. Сохраните прежнюю папку состояния и исходные пути; не подменяйте их вручную в SQLite. Подробнее: [перенос существующего состояния](docs/TRUENAS_RU.md#перенос-существующего-состояния).

## Данные и доступ

Панель рассчитана на доверенную локальную сеть. При HTTP трафик браузера не шифруется; для удалённого доступа используйте HTTPS reverse proxy или защищённый туннель. Первый открывший новую панель задаёт её пароль, поэтому выполните начальную настройку сразу после запуска.

Состояние содержит токены входа в Mail и сведения о файлах. Храните его на локальном filesystem, на TrueNAS — в отдельном локальном ZFS dataset, вне SMB/NFS и папок облачной синхронизации. Не публикуйте `/state`, `.env`, отчёты диагностики или логи вместе с исходниками. Пароль Mail вводится в панели и не сохраняется как пароль; токены сохраняются для продолжения работы.
