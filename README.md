# mail_cloud

Загрузчик фото и видео в Облако Mail с управлением через браузер. Работает на сервере или NAS: выбираете папки, запускаете загрузку и следите за очередью. Вкладку можно закрыть — файлы продолжат загружаться.

Приложение сохраняет структуру папок, показывает прогресс и ошибки, умеет ставить загрузку на паузу и продолжать после перезапуска. Можно отдельно остановить, повторить или убрать задачу и очистить очередь. Ошибка одного файла не мешает обработке остальных. Из очереди можно открыть фотографию, скачать исходник или перейти к загруженному файлу в Облаке. Панель показывает занятую и доступную квоту. Исходные файлы не изменяются.

Клиент находит фотографии `jpg`, `jpeg`, `png`, `heic`, `heif`, `webp`, `gif` и видео, включая `mp4`, `mov`, `mkv`, `avi`, `webm`. [Полный список форматов и ограничения](docs/WEB_GUI_RU.md#фото-и-видео).

Файлы больше 2 ГБ пропускаются с объяснением в очереди. Обычная загрузка таких файлов в этой версии отсутствует.

Это неофициальный клиент; для входа нужен аккаунт Mail и пароль внешнего приложения с доступом к Облаку.

## Установка на TrueNAS

Подходит для **TrueNAS SCALE 24.10 и новее**, где приложения работают через Docker. Готовый образ рассчитан на Intel/AMD (`linux/amd64`), вход в GitHub для скачивания не нужен.

1. Создайте отдельный dataset для состояния приложения. Определите каталог с фото и видео.
2. Откройте [deploy/truenas-compose.yaml](deploy/truenas-compose.yaml). Замените два пути `/mnt/CHANGE_ME/...` на свои и укажите адрес NAS в `MAILRU_ALLOWED_HOSTS`.
3. Проверьте `user: "1000:1000"`: выбранному UID/GID нужны запись в dataset состояния и чтение исходных файлов. Для пользователя TrueNAS `apps` можно указать `568:568`, выдав ему эти права.
4. В **Apps → Discover Apps → ⋮ → Install via YAML** задайте имя `mail-cloud`, вставьте YAML и сохраните.
5. Дождитесь запуска и откройте `http://<адрес-NAS>:31800`.

Порт в шаблоне — `31800:8787`. В `MAILRU_ALLOWED_HOSTS` нужен IP или DNS-адрес NAS без `http://` и порта; это настройка доступа к панели, а не привязка Docker к сетевому интерфейсу.

[Подробная инструкция TrueNAS](docs/TRUENAS_RU.md) описывает права, подключение нескольких dataset и возможные ошибки запуска.

## Установка через Docker Compose

Для обычного Linux-сервера:

```bash
git clone https://github.com/zhalenik/mail_cloud.git
cd mail_cloud
cp .env.example .env
```

В `.env` укажите существующие каталоги `STATE_DIRECTORY` и `PHOTO_LIBRARY`, UID/GID пользователя контейнера и адрес сервера в `MAILRU_ALLOWED_HOSTS`. Затем запустите:

```bash
docker compose config
docker compose pull
docker compose up -d
```

Панель будет доступна по адресу `http://<адрес-сервера>:31800`.

## Первый запуск

При первом открытии задайте пароль панели длиной от 12 символов. Это отдельный пароль, не пароль Mail.

В панели подключите аккаунт Mail и добавьте источник фото и видео. Для каждого источника выберите отдельную папку назначения в Облаке. В стандартном контейнере это `/photos` или его подпапки. Если панель открыта с другого компьютера, в ней всё равно выбираются папки сервера.

Короткое имя помогает различать источники в интерфейсе. При назначении `/PhotoArchive/Family` файл `/photos/2024/photo.jpg` попадёт в `/PhotoArchive/Family/2024/photo.jpg`; имя источника к пути не добавляется. Назначение можно изменить, а ненужный источник — убрать вместе с его задачами. Исходники на диске и ранее загруженные файлы останутся на месте.

Нажмите **«Начать загрузку»**. Клиент сам просканирует папки и создаст очередь. В ней видны текущие задачи загрузки, завершённые задачи и ошибки. Повторное сканирование обновляет состав очереди: исчезнувшие файлы не увеличивают её счётчики.

- **«Приостановить»** останавливает загрузку с сохранением прогресса.
- **«Продолжить загрузку»** возвращает в работу незавершённые задания.
- **«Найти новые файлы»** обновляет очередь после добавления фото или видео в исходные папки. Постоянного наблюдения за каталогами нет.

В настройках можно выбрать число одновременных загрузок и включить продолжение после перезапуска. По умолчанию загружаются два файла одновременно. Ручная пауза сохраняется и после перезапуска.

Для выхода из аккаунта нажмите на логин справа вверху и выберите **«Выйти из Mail.ru»**. Клиент остановит текущую работу и удалит сохранённый вход. Очередь останется: чтобы продолжить, подключите тот же аккаунт. Отдельная кнопка **«Выйти из панели»** закрывает доступ к управлению, а загрузка продолжает работать.

Сверку с существующими файлами можно включить в настройках. После сканирования клиент сравнит назначенный облачный путь, размер и содержимое; совпавшие задачи получат отметку «Уже в Облаке». По умолчанию сверка выключена, поскольку на большом архиве она увеличивает время проверки. Пароль панели также меняется в настройках.

## Обновление

Чтобы получать новые выпуски без ручной замены номера версии, один раз откройте **Apps → mail-cloud → Edit** и укажите у сервиса обе строки:

```yaml
image: ghcr.io/zhalenik/mail_cloud:stable
pull_policy: always
```

В новом шаблоне они уже есть; YAML ранее установленного приложения нужно поправить на самом NAS. Остальные параметры своего приложения сохраните.

Для следующего обновления нажмите **«Приостановить»** в панели, затем **Stop** в TrueNAS. Сделайте снимок dataset состояния и нажмите **Start**: TrueNAS проверит `stable` в registry и запустит актуальный образ. После запуска проверьте версию в панели и продолжите очередь.

Кнопка **⋮ → Update** тоже может использоваться, когда TrueNAS обнаружит новый образ. На SCALE 24.10 она требует запущенного приложения и может появиться не сразу. [Подробнее об обновлении](docs/TRUENAS_RU.md#обновление).

Очередь, настройки и вход в Mail хранятся в `/state`. Сохраните тот же dataset, UID/GID и пути источников внутри контейнера — тогда новая версия продолжит работу с существующей очередью.

Для Docker Compose после резервной копии состояния выполните `docker compose pull` и `docker compose up -d`.

Для фиксации определённого выпуска используйте тег, например `ghcr.io/zhalenik/mail_cloud:v0.5.2`. [Список выпусков](https://github.com/zhalenik/mail_cloud/releases) и [история изменений](CHANGELOG.md).

Панель предназначена для локальной сети. Для доступа извне настройте HTTPS или VPN. В `/state` находятся токены аккаунта: храните этот каталог отдельно от общих сетевых папок и не добавляйте его в репозиторий.

Об ошибках можно написать в [Issues](https://github.com/zhalenik/mail_cloud/issues). Укажите версию приложения и текст ошибки; пароли, токены и папку состояния прикладывать не нужно.
